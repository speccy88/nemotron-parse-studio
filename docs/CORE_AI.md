# Core AI execution and conversion

Nemotron parsing now executes end-to-end in **Swift/Core AI on macOS 27.2.1**, using CPU float32. Both included geometries, 512 × 256 and 640 × 800, produced byte-for-byte identical serializations to pinned PyTorch CPU inference, including table values, chart percentages, multilingual text, classes, and bounding boxes. These are two synthetic functional fixtures, not corpus-wide accuracy evidence.

The original macOS 26 investigation is preserved in [CORE_AI_INITIAL_INVESTIGATION.md](CORE_AI_INITIAL_INVESTIGATION.md). Its unavailable-native and HTTP-transport statements are historical and superseded here.

## Fixing the two vision blockers

The original export failed on `aten._upsample_bilinear2d_aa.default` and `aten.grid_sampler_2d.default`. Both transform the learned positional field for the padded/content geometry; neither depends on page pixel values.

`Conversion/vision_geometry.py` evaluates NVIDIA's original `_normalized_2d_position_pages` once during export for each exact geometry and frozen learned field. Positions become a constant buffer. The patch embedder, class tokens, 27 vision transformer blocks, and adapter remain unchanged. Neither antialiasing nor grid sampling is approximated or disabled. No page text, prediction, or sample pixels become model weights.

The app verifies exact content/padded dimensions; it never silently resizes a document to fit. The geometry test compares the original and specialized paths at seven height/width pairs: `(1,1)`, `(16,31)`, `(31,16)`, `(17,63)`, `(253,509)`, `(800,640)`, `(321,961)`. Results are bit-exact and both unsupported operators are absent from the specialized export graph.

## Native pipeline

1. ImageIO/Core Graphics produce white-backed RGB pixels. Swift applies the original normalization and 16 × 16 patch ordering. The two validation patch tensors are bit-identical to PyTorch.
2. A geometry-specific `encoder.aimodel` executes vision and the adapter.
3. A matching `prefill.aimodel` inserts full-structure control IDs `[2,0,50004,50008,50001,50009]` and initializes explicit KV tensors.
4. `decoder-step-1024.aimodel` updates the cache slot with its causal mask. Swift performs greedy selection, repetition penalty, cancellation checks and EOS stopping.
5. Swift decodes original ByteLevel vocabulary bytes as a combined stream, handling UTF-8 spanning token boundaries.
6. NVIDIA's pinned helpers format the serialization through the private persistent `--stdio` worker. This formatting step is separately identified as Python work.

Loading/execution use `CoreAI.AIModel`, `.cpuOnly`, and `InferenceFunction.run`. `Sources/NativeValidate/main.swift` exercises the same native engine independently of the GUI. Python does not execute the native model.

Gates: exact patches, visual relative L2 below `1e-3`, prefill logit max error below `1e-3`, and **exact final serialized prediction**. Model tensors are not claimed to be bit-identical. Export-time partition tests also compare decoder cache updates and logits against the original PyTorch model. Final serialization checks exercise repeated native cache updates, EOS, token decoding and coordinates.

Comparison settings: single pass, CPU float32, temperature 0, repetition penalty 1.05, picture-text enabled, maximum 256 generated tokens. Earlier standalone references used penalty 1.1 and are not the basis of this equality claim. Individual timings have different load/cache states; they do not rank backends or multipass modes.

## Reproduction

Use isolated Python 3.12 conversion dependencies `coreai-core==1.0.0b3`, `coreai-torch==0.4.3`, and `torch==2.11.0`. The tested conversion environment is `Conversion/.venv-conversion`. Reference validation uses the interpreter that invokes it. Package locks are retained with the evidence.

From the workspace root, after installing the pinned model:

```sh
Backend/.venv/bin/python -m pytest -q Conversion/tests
Conversion/.venv-conversion/bin/python Conversion/export_native.py \
  --image Conversion/evidence/pages/simple.png --output NativeModels
Conversion/.venv-conversion/bin/python Conversion/export_native.py \
  --image Conversion/evidence/pages/mixed.png --output NativeModels
swift build -c release --product NativeValidate
.build/release/NativeValidate NativeModels Conversion/evidence/pages/simple.png \
  Conversion/evidence/native-swift-simple 256
.build/release/NativeValidate NativeModels Conversion/evidence/pages/mixed.png \
  Conversion/evidence/native-swift-mixed 256
Backend/.venv/bin/python Conversion/validate_native.py
```

Export requires a new asset path. To repeat validation with existing assets, start at the Swift build step. New profiles are `validated: false` and the validation executable can load them for comparison. `validate_native.py` promotes the two profiles only after all gates pass.

## Boundaries

- Only the two exact validated geometries are accepted. Dynamic geometry and more profiles need additional exports and validation.
- Native inference is single pass and greedy. Sampling and double/triple pass use the reference backend.
- Cache capacity is 1024 including visual/control prefixes: 889 generation tokens for simple, 517 for mixed. Excess settings are rejected before loading; the tested preset is 256.
- CPU is validated; GPU/ANE/automatic compute are not enabled or claimed.
- Broader languages, complex layouts, long generations and high-resolution performance remain to be evaluated.
- Older assets under `Conversion/evidence/coreai-adapter-decoder` remain historical experiments. The app loads `NativeModels`.
